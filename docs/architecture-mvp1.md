# Архитектура MVP 1

Дата фиксации: 2026-09-04.

## Задача

MVP 1 доказывает только передачу текста между Android и браузером Windows в обе стороны. Файлы сознательно исключены до реального успешного теста текстового цикла.

## Зафиксированная среда

- Google Pixel 7.
- Android 17 / API 37.
- Windows-клиент без устанавливаемого ПО.
- Основной браузер: Microsoft Edge.
- Основной сетевой сценарий: телефон и ПК подключены к одной Wi-Fi/LAN.
- После базового LAN-теста отдельно проверяется сценарий, где Pixel 7 сам раздаёт Wi-Fi клиентскому ПК.
- Karing может постоянно работать в TUN-режиме. Local Bridge допускается исключить из проксирования Karing.
- Распространение приложения: APK через GitHub, без Google Play.

## Стек

- Kotlin.
- Android SDK.
- Jetpack Compose.
- Foreground service для жизни локального сервера при свёрнутом Activity.
- Ktor Server + CIO для встроенного HTTP-сервера.
- Чистые HTML/CSS/JavaScript для Windows-клиента.
- Server-Sent Events (SSE) для push-событий Android → браузер.
- Обычные HTTP POST для браузер → Android.

## Почему SSE, а не WebSocket

Для MVP постоянный realtime-канал требуется только от Android к браузеру. В обратную сторону браузер отправляет отдельные HTTP-запросы. SSE проще, автоматически переподключается через `EventSource` и не требует двустороннего socket-протокола.

## Планируемый поток текста

### ПК → телефон

1. Edge открывает локальную страницу телефона.
2. Пользователь вставляет текст в большое поле.
3. Страница делает `POST /api/clipboard`.
4. Android-сервис вызывает `ClipboardManager.setPrimaryClip()`.
5. Страница показывает результат операции.
6. Пользователь открывает ChatGPT на телефоне и вставляет текст обычным системным способом.

### Телефон → ПК

1. Пользователь копирует текст в ChatGPT.
2. Открывает Local Bridge.
3. Нажимает `ОТПРАВИТЬ БУФЕР НА ПК`.
4. Activity, находясь на переднем плане, читает `ClipboardManager.getPrimaryClip()`.
5. Значение передаётся серверному состоянию.
6. Сервер отправляет SSE-событие подключённым браузерам.
7. Edge обновляет отображаемый текст без F5.
8. Пользователь нажимает `КОПИРОВАТЬ` и вставляет текст в PowerShell.

## Android clipboard

Фоновое чтение системного clipboard не является частью архитектуры. Современный Android ограничивает чтение clipboard приложениями без фокуса. Local Bridge читает clipboard только после явного действия пользователя в открытом Activity.

Запись текста из входящего LAN-запроса в системный clipboard выполняется серверной частью приложения через `ClipboardManager.setPrimaryClip()`.

## Локальная сеть на Android 17

Приложение будет собираться с `targetSdk = 37`. Android 17 требует runtime-разрешение `android.permission.ACCESS_LOCAL_NETWORK` для прямого локального сетевого обмена приложений, таргетящих API 37+. Перед запуском HTTP-сервера разрешение должно быть получено и его отзыв должен обрабатываться без падения приложения.

## Foreground service

Локальный сервер должен жить в foreground service, чтобы продолжать работу после сворачивания Activity. Планируемый тип сервиса — `connectedDevice`, поскольку сервер поддерживает сетевое взаимодействие с внешним клиентским устройством.

Сервис запускается только из видимого приложения. Автоматический скрытый запуск из фона в MVP не нужен.

## Сеть

Сервер не должен определять IP через абстрактную «активную сеть», поскольку Karing создаёт VPN/TUN. Для отображения адреса Local Bridge должен явно искать физическую Wi-Fi-сеть через `ConnectivityManager` / `TRANSPORT_WIFI`.

При изменении Wi-Fi состояния адрес в UI должен обновляться. Устойчивое переподключение после смены сети добавляется после подтверждения базового сервера.

## HTTP API — минимальный контракт

Планируемые маршруты MVP 1:

- `GET /` — веб-интерфейс.
- `POST /api/auth` — ввод PIN и создание локальной сессии.
- `POST /api/clipboard` — ПК → Android clipboard.
- `GET /api/state` — текущее состояние для первоначальной загрузки/восстановления.
- `GET /events` — SSE-поток Android → браузер.

Контракт может быть упрощён в ходе первого smoke-test, но не должен расширяться без практической необходимости.

## Кнопка «Копировать» в Edge

Страница работает по обычному локальному HTTP, например `http://192.168.1.123:8765`. Современный `navigator.clipboard` нельзя считать гарантированно доступным в таком контексте. Реализация должна иметь fallback для Edge; HTTPS и собственные сертификаты ради этой кнопки в MVP не вводятся.

## Безопасность

После проверки базового сетевого обмена добавляется минимальная локальная авторизация:

- случайный PIN для подключения;
- после успешного PIN — случайная session cookie;
- API и SSE закрыты без сессии;
- CORS не разрешается;
- TLS/HTTPS в MVP не используется.

PIN — защита от случайного/чужого устройства в общей локальной сети, а не криптографическая защита от атакующего, способного перехватывать LAN-трафик.

## Что сознательно не входит в MVP 1

- Передача файлов.
- База данных.
- История сообщений.
- WebSocket.
- HTTPS и собственный CA.
- mDNS.
- QR pairing.
- Root.
- Shizuku.
- Accessibility Service.
- Фоновое слежение за clipboard.
- Кнопка в шторке Android.
- Автозапуск после перезагрузки.

## Порядок реализации

1. Минимальное запускаемое Android-приложение.
2. Локальный HTTP-сервер и простая тестовая страница.
3. Проверка доступа Edge → Pixel 7 в общей Wi-Fi/LAN.
4. ПК → Android clipboard.
5. Android clipboard → ПК через кнопку приложения и SSE.
6. Проверка foreground service при переключении в ChatGPT.
7. PIN + сессия.
8. Отдельная проверка hotspot телефона + Karing.
9. Только после PASS всех основных текстовых сценариев — MVP 2 с файлами.
